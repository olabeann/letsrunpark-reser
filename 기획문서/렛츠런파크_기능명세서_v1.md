## 01 문서 목적과 적용 범위

현재 예약·운영 관리자·계정 화면을 기준으로 사용자 동작과 검수 기대 결과를 정의한다. 최신 화면의 입력·안내·실제 동작을 기존 회의·정책 문서보다 우선한다. 화면 내부의 안내와 동작이 다르면 실제 동작과 남은 차이를 함께 기록한다.

‘현행’은 프로토타입 화면에 있는 기능, ‘연동’은 실제 인증·PG·서버 구현 요구, ‘추가 확인’은 화면만으로 정할 수 없는 정책이다. 화면 존재나 자동 검사 통과가 실서비스 완료를 뜻하지 않는다. 계약 금액·납기·견적 범위는 계약 자료로 별도 확인하며 이번 개정으로 변경하지 않는다.

서울 포니 타기·포니랑 놀기가 현재 판매 화면의 대상이다. 부산경남·제주는 준비 중 안내이며 향후 프로그램을 같은 구조로 확장한다. 기능 ID는 기존 USR·RSV·CART·ORD·TKT·CAN·ADM·OPS 및 D·AT 식별자를 유지한다. IA와 화면 정책 도구의 ID는 별도 체계다.

## 02 최신 화면 기준 핵심 정책

- 예약 화면 하나에서 체험·날짜·회차·인원·할인을 선택한다.
- 다른 프로그램의 회차가 동일 계정의 기존 유효 예약 또는 장바구니와 이용 시간이 겹치면 차단한다. 같은 프로그램의 같은 회차는 재고와 구매 한도 안에서 여러 매 구매할 수 있다. 종료 시각과 다음 시작 시각이 같으면 허용하며 이동·준비시간은 추가하지 않는다.
- 장바구니는 동일 이용일·지역·담당부서만 허용한다. 같은 회차 반복 담기가 가능하다.
- 선택한 인원수만큼 1명 카드를 생성한다. 장바구니는 카드별 삭제를 제공하며 수량 증감·자동 병합은 하지 않는다.
- 장바구니와 결제 진입 시 정원을 선점하지 않는다. 결제 확정 시 재고를 다시 확인한다.
- 결제당 예약번호는 하나다. 신규 주문은 카드별 하위 티켓을 만들고 사용자 목록은 예약번호로 묶는다.
- 사용자가 직접 취소 인원을 선택하고 해당 티켓의 결제 당시 배분액을 환불받을 수 있다.
- 계정은 통합 관리자와 부서 공용 관리자의 고정 권한으로 구분한다.
- 정산은 실제 서비스 완료월 기준이며 다음 달 8일 지급 예정이다. PG 수수료는 2%이며 취소 시 같은 비율을 음수 조정한다.
- 고객 자동 알림은 현재 발송하지 않는다. 운영 취소 확인 화면에도 미발송을 안내한다.

## 03 회원과 예약 옵션

### USR-01 통합 회원과 간편 로그인

네이버·카카오 로그인 회원만 예약한다. 제공자가 다른 계정은 별도 회원으로 식별하고 장바구니·예약을 계정별로 분리한다. 현재 로그인은 모의 동작이며 실제 소셜 인증과 서버 회원 검증은 연동 대상이다. 회원탈퇴의 보관·삭제 정책은 D-09에서 추가 확인한다.

### USR-02 체험 선택

포니 타기·포니랑 놀기를 예약 화면에서 선택한다. 별도 상품 목록·상세 페이지를 전제로 하지 않는다. 프로그램별 이미지·가격·안내를 표시하고 기존 콘텐츠의 예약 CTA도 해당 체험으로 연결할 수 있다. 현재 투어 소개 페이지는 없으며 기존 투어 예약 기록은 호환 목적으로 표시할 수 있다.

### USR-03 날짜와 회차

프로그램의 운영 기간·요일, 노출 기간, 오늘부터 N일 뒤까지의 예약 가능 일수, 휴장과 회차 판매 상태를 반영한다. 기본 N은 14이며 관리자에서 프로그램별로 바꿀 수 있다. 날짜·회차는 직접 선택하며 선택 불가 시 다른 회차로 자동 대체하지 않는다. 시간 중복은 재고 마감과 구분하여 담기·결제 검증에서 제한한다.

### USR-04 인원과 할인

프로그램별로 계정당 이용일별 최대 구매 수량을 설정한다(기본 4매). 같은 프로그램·이용일의 모든 회차·주문에 대해 기존 유효 예약과 장바구니 수량을 합산하고 취소 완료 수량은 제외한다. 다른 프로그램의 구매 수량은 합산하지 않는다. 과천시민 할인은 50%, 같은 이용일 계정당 최대 2매다. 프로그램·주문을 나눠도 합산한다.

할인은 ‘할인 미적용’을 기본으로 한 정책만 선택한다. 동일 계정·이용일에는 기존 예약을 포함해 할인 정책 하나만 적용한다. 할인으로 선택한 인원은 모두 해당 할인으로 담고, 정상가 인원은 미적용으로 따로 담는다. 모든 장바구니 카드는 1명 단위다. 과천시민 증빙은 현장 확인하며 미제출 처리는 추가 확인한다.

관리자의 할인 집계 기준·복원 설정과 사용자 계산 연결에는 S-03의 차이가 있다. 이용 전 확인사항은 내용이 있으면 체크 후 예약을 진행한다. 확인 필수 설정과의 차이는 S-04에 기록한다.

### USR-05 예약 조회

본인 예약을 공통 예약번호별로 조회하고 하위 티켓의 일정·인원·할인·결제·취소 내역을 확인한다. 표시 건수와 무관하게 계정의 유효 예약 수량 전체를 구매·할인 한도에 합산한다. 타인 예약은 서버에서도 차단해야 한다.

## 04 예약 검증과 장바구니

### RSV-01 프로그램 간 시간 중복 제한

다른 프로그램의 회차가 동일 계정의 기존 유효 예약 또는 장바구니와 이용 시간이 겹치면 차단한다. 같은 프로그램의 같은 회차는 재고와 구매 한도 안에서 여러 매 구매할 수 있다. 종료 시각과 다음 시작 시각이 같으면 허용하며 이동·준비시간은 추가하지 않는다. 같은 결제 요청의 중복 처리는 별도로 방지한다.

### RSV-02 검사 범위와 시점

담기·주문 진입·결제 확정 시 인증 계정, 이용일·지역·부서, 운영 일정, 구매·할인 수량과 금액을 다시 검사한다. 결제 확정 시 회차 재고를 검사한다. 실서비스는 서버에서 최신 데이터와 동시 요청을 기준으로 초과 판매·한도 초과를 막는다.

### CART-01 담기

선택 N명은 1명 카드 N개로 추가한다. 같은 상품·날짜·회차를 반복해서 담을 수 있고 기존 카드와 합치지 않는다. 한도 초과나 다른 이용일·지역·부서이면 기존 장바구니를 유지하고 사유를 안내한다. 기존 카드가 있는 상태에서 바로 예약하면 함께 확인할 장바구니로 이동한다.

### CART-02 확인과 삭제

체험·일정·정상가 또는 할인 여부·카드 금액·합계를 표시한다. 카드별 삭제만 제공하며 추가 인원은 예약 화면에서 담는다. 결제 완료된 장바구니는 비운다. 담기·결제 진입만으로 정원을 확보하지 않고, 일부 회차가 결제 시 마감되면 전체 결제를 완료하지 않으며 장바구니를 유지한다.

| 상황 | 기대 결과 |
| --- | --- |
| 같은 이용일의 10시와 10시 10분 회차 | 다른 프로그램이면 차단, 같은 프로그램의 같은 회차는 재고·한도 내 허용 |
| 같은 상품·회차를 다시 담기 | 1명 카드 추가, 기존 카드와 자동 병합하지 않음 |
| 다른 이용일·지역·부서 추가 | 혼합 담기 차단, 기존 결제 또는 비우기 안내 |
| 같은 프로그램·이용일의 설정 한도까지 유효 예약 후 추가 | 구매 한도 초과로 차단 |
| 다른 이용일 새 주문 | 해당 이용일 한도로 다시 계산 |

## 05 주문과 결제 및 티켓

### ORD-01 일괄 예약

같은 이용일·지역·담당부서의 카드를 한 예약으로 결제한다. 최종 상품·일정·금액을 확인하고 서버에서 가격·할인·재고를 검증해야 한다. 동의 없이 가능한 항목만 골라 부분 결제하거나 변경 금액으로 승인하지 않는다.

### ORD-02 카드 결제

현재 제공 수단은 카드다. 초기 위이 PG 방향을 유지하되 실제 PG·계약·카드 승인·부분취소 조건은 연동 단계에서 확인한다. 간편결제·계좌이체는 현재 제공 기능에 포함하지 않는다. PG 승인 확인 전 예약을 완료로 표시하지 않으며 중복 요청·응답 지연·승인 후 저장 실패에 대한 조회·복구를 구현해야 한다.

### TKT-01 사용자 티켓

결제당 LRP-YYMMDD-NNNNN 형식의 예약번호 하나를 사용한다. 상품별 -1·-2 접미사는 붙이지 않는다. 현재 신규 주문은 1명 카드별 하위 티켓을 생성하고 목록은 공통 예약번호로 묶는다. 같은 회차를 무조건 한 장으로 합치는 정책 설명과 복수 인원 예시 데이터는 실제 신규 흐름과 다르므로 S-02로 관리한다.

### TKT-02 관리자 인원별 티켓

관리자는 예약번호 아래 인원별 티켓 식별자, 상품·회차·결제 당시 할인·배분 금액·상태·취소 이력을 확인한다. 티켓 번호와 PG 거래번호는 예약번호와 별개다. 인원별 식별이 참석자 실명 수집을 의미하지 않으며 현재 흐름에 없는 실명 입력을 추가 요구로 간주하지 않는다.

### TKT-03 입장 상태

시간에 따라 입장 대기·입장 가능·입장 종료를 표시한다. 입장 가능 시작은 프로그램의 입장 대기 시간 전이며 기본 20분, 설정 범위는 0~100분이다. 입장 가능 표시와 움직이는 티켓은 실제 사용 완료 기록이나 QR 검표를 대신하지 않는다. 취소 완료 인원은 유효 인원에서 제외한다.

## 06 취소와 환불

### CAN-01 사용자 직접 취소

사용자는 티켓 상세에서 인원을 선택하고 환불 예정액을 확인한 후 부분·전체 취소한다. 실제 버튼은 입장 대기이면서 설정된 취소 마감 전일 때만 활성화한다. 기본 마감 설정은 10분 전이지만 기본 20분 전 입장 가능 전환부터 취소가 막히므로 S-01을 함께 적용한다.

### CAN-02 관리자 취소

담당 범위의 인원별 티켓을 선택해 취소한다. 관리자 계정·처리 시각·사유·대상·금액을 기록한다. 통합 관리자는 전체, 부서 관리자는 자기 부서만 처리한다. 운영상 휴장은 기존 예약 유지 또는 전체 취소·환불 중 선택한다. 운영 취소 권한은 사용자 취소 마감과 구분한다.

### CAN-03 금액과 한도 복원

선택한 티켓의 결제 당시 배분액 합계를 환불 예정액으로 사용한다. 남은 티켓의 할인·금액은 재계산하지 않는다. 현재 화면은 별도 고객 취소수수료를 차감하지 않는다. PG 수수료 2%와 고객 취소수수료를 혼용하지 않는다. 취소 완료 수량을 구매 한도에서 제외하고 남은 인원만 집계한다. 할인 복원 설정 연결 차이는 S-03을 따른다.

### CAN-04 실패와 처리 이력

현재 프로토타입의 완료 표시와 실제 PG 환불은 구분한다. 실서비스는 동일 티켓 재취소와 원 결제액을 넘는 환불을 막고, 결과 불명확·실패는 거래 조회 후 재처리해야 한다. 관리자 예약 배지는 확정·부분 취소·취소 완료 3종이며, 환불 처리 중·실패 상태를 해당 예약 배지에 이미 구현한 것으로 쓰지 않는다. 외부 거래 처리 상태는 별도 설계 대상이다.

## 07 관리자 권한과 프로그램 운영

### ADM-01 고정 역할과 데이터 범위

| 역할 | 허용 범위 |
| --- | --- |
| 예약 회원 | 본인 장바구니·예약·티켓·취소 |
| 부서 공용 관리자 | 자기 부서 프로그램·회차·운영일·예약·환불·정산 관리, 타 부서 프로그램 조회 |
| 통합 관리자 | 전체 지역·부서 관리, 부서 계정 발급·수정·비밀번호 재발급·삭제 |

기능별 권한 체크박스는 현재 범위에 없다. 통합 관리자 삭제를 금지하고 부서 계정은 연결 프로그램·업무 이력이 있으면 삭제를 막는다. 로그인 이력만으로는 제한하지 않는다. 삭제 성공 시 서버 세션도 만료해야 한다. 공용 계정의 기록은 개인 이름이 아니라 계정 ID·지역·부서·시각·사유를 남긴다.

### ADM-02 프로그램 등록과 노출

프로그램을 먼저 등록하고 회차를 추가한다. 지역·부서·유형·이름·기본 가격·대표 이미지·요약 안내·이용 전 확인사항·운영 기간과 요일·노출 기간·예약 가능 N일·입장 대기·취소 설정·할인을 관리한다. 신규 대표 이미지는 필수, 요약 안내 문구는 선택이다. 숨김은 신규 노출을 중단하며 기존 예약 이력을 지우는 것과 다르다.

### ADM-03 회차와 운영일

회차 시작·종료 시각, 온라인 수량, 판매 상태를 설정하고 시간순으로 회차명을 자동 생성한다. 온라인 수량은 키오스크와 연동하지 않는다. 예약 수보다 작은 정원, 종료가 시작보다 이른 설정 등 유효하지 않은 변경을 차단한다. 예약 시간·금액은 구매 당시 기준을 보존한다. 운영 달력은 운영·일부 휴장·휴장을 구분한다.

### ADM-04 할인 관리

프로그램과 분리된 할인에 정률·정액·최대 할인금액·수량·집계 기준·기간·증빙·취소 복원·적용 프로그램·활성을 설정한다. 할인 변경은 신규 예약에 적용하고 기존 결제 스냅샷을 보존한다. 복수 할인명 표시는 우선순위가 아니다. 사용자 적용은 이용일당 하나의 할인 정책이며 S-03 연결 차이를 구분한다.

## 08 예약 운영과 정산 및 인프라

### ADM-05 예약 조회와 휴장

예약번호별 한 행에 상품·회차를 묶어 표시하고 상세에서 인원별 티켓을 확인한다. 구매금액은 최초 할인 적용 구매액, 결제금액은 구매금액에서 환불 누계를 뺀 값이다. 검색·필터는 함께 적용하며 목록은 페이지당 20건이다. 휴장 확인에서는 대상 예약과 환불 예정액을 확인하고 유지 또는 취소·환불을 선택한다. 고객 자동 알림은 발송하지 않는다.

### ADM-06 매출과 정산

실제 서비스 완료월을 기준으로 매월 1일부터 말일까지 집계하고 다음 달 8일 지급 예정으로 표시한다. 서비스 전 전액취소·미완료 건은 제외하고 완료 전 부분취소를 반영한다. 승인액에서 취소액을 빼면 순매출, 순매출에서 수수료를 빼면 지급예정액이다. PG 수수료는 거래금액의 2%이며 취소는 동일 비율 음수 조정이다. 지급예정액은 실제 송금 완료액이 아니다.

### ADM-07 정산 다운로드

서비스 이용일·지역·부서·카드사·예약번호·상품명 조건을 화면과 엑셀에 동일하게 적용한다. 원장은 예약번호별 한 행, 펼친 이력은 승인·취소 원본 이벤트다. 엑셀은 매출 요약·결제 정산 원장·거래 이력 3개 시트이며 포트원 거래번호·취소 티켓 번호·사유는 거래 이력에 포함한다. 세금·면세·수수료 공급가액·부가세를 별도 표시하지 않는다. 자동 송금은 포함하지 않는다.

### OPS-01 운영 인프라

위이가 외부 서버·DB를 운영하고 신규 도메인을 적용하는 기존 구축 방향을 유지한다. 실제 인증·권한·감사 로그·백업·복구·모니터링은 연동·운영 요구다. 보안·개인정보 세부 기준과 비용은 담당자·계약 자료로 확인한다.

### OPS-02 오픈과 검수

부산경남·제주는 준비 중 안내다. 실제 지역·프로그램·CTA 오픈 대상과 일정을 별도 확정하고 실제 로그인·PG·서버 통합 검수 후 공개한다. 과거 회의의 목표 날짜를 확정 납기로 해석하지 않는다.

## 09 주문과 데이터 보존 기준

회원 아래 예약, 예약 아래 하위 티켓과 결제·환불 거래를 연결한다. 인원별 티켓에는 결제 당시 상품·회차·지역·부서·할인·금액과 입장·취소 설정을 보존한다. 식별자는 예약번호, 인원별 티켓 번호, 결제 거래번호, 환불 요청 번호로 구분한다.

인원별 결제 배분액 합계는 원 구매액과 같아야 하고 환불 누계는 원 승인액을 넘을 수 없다. 취소 후 원 구매액은 유지하며 남은 결제액·유효 인원을 별도 계산한다. DB 테이블·트랜잭션·재시도 구현은 개발팀 설계 대상이다.

## 13 구현 현황과 전달 자료

화면은 프론트엔드 프로토타입이며 예약은 브라우저 저장소, 정산은 예시 데이터로 동작한다. 실제 로그인·PG·DB·권한·동시성·환불 통합 검수가 필요하다. 관련 자동 검사는 프로토타입 논리를 확인하며 S 항목이나 운영 연동 완료를 보장하지 않는다.

마사회는 로그인 앱·개발 권한, 도메인, 실제 운영값·오픈 대상·CTA, 현장 검표·증빙·연락 기준과 정산 행정 자료를 제공한다. 위이는 실제 PG 조건, 서버·티켓·환불 설계, 정책별 검수와 개발 일정을 준비한다. 양사는 잔여 D 항목과 S 항목의 처리 결과·적용일·기존 예약 영향을 기록한다.
