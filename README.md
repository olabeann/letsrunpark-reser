# PONYLAND 체험 상품 예약

서울 렛츠런파크의 **포니 타기·포니랑 놀기** 두 상품을 예약하는 커머스형 프론트엔드 프로토타입입니다.

## 공유 링크

| 페이지 | 바로가기 |
| --- | --- |
| 메인 예약 화면 | [사이트 열기](https://olabeann.github.io/letsrunpark-reser/) |
| 포니 타기 | [상품 보기](https://olabeann.github.io/letsrunpark-reser/?product=ride) |
| 포니랑 놀기 | [상품 보기](https://olabeann.github.io/letsrunpark-reser/?product=play) |
| 장바구니 | [장바구니 열기](https://olabeann.github.io/letsrunpark-reser/?view=cart) |
| 포니 체험 소개 | [소개 페이지 열기](https://olabeann.github.io/letsrunpark-reser/pony.html) |

| GitHub 저장소 | [코드 보기](https://github.com/olabeann/letsrunpark-reser) |

티켓 목록과 상세 화면은 **예약 조회 → 카카오로 계속하기 또는 네이버로 계속하기 → 티켓 선택** 순서로 확인할 수 있습니다.

## 이용 안내

- 디자인과 예약 흐름을 확인하기 위한 시연용 사이트입니다. 실제 예약·입장에 사용할 수 없습니다.
- 간편 로그인과 결제는 실제 서비스에 연결되어 있지 않습니다.
- **상품 목록 → 상품 상세(날짜·시간·인원) → 장바구니 → 주문·결제 → 예약 완료** 순서입니다. 목록에는 포니 타기와 포니랑 놀기만 표시합니다. 옵션을 선택한 뒤 담으면 쇼핑 계속하기/장바구니 보기 안내가 열립니다.
- 장바구니는 상품 선택 화면과 분리되어 있으며, 인원 변경·삭제와 상품 금액·할인·총액을 확인할 수 있습니다. 주문 화면에서는 상품을 읽기 전용으로 확인하고, 변경은 장바구니에서 합니다. 날짜와 회차는 사용자가 명시적으로 선택해야 합니다.
- 상품·장바구니 URL은 새로고침과 브라우저 뒤로가기를 지원합니다. 결제 화면으로 직접 진입하거나 돌아오는 경우에는 장바구니에서 다시 확인합니다. 기존 `?program=...` 링크는 두 상품 목록으로 연결됩니다.
- 같은 계정의 기존 예약과 장바구니 전체를 합쳐 이용 시간이 겹치면 차단합니다. 시작 시각만 비교하지 않으며, 투어는 기존 안내의 80분을 적용합니다. 앞 회차의 종료 시각과 다음 회차의 시작 시각이 같으면 예약할 수 있습니다.
- 로그인 창에서 카카오/네이버와 회원 1/2를 선택합니다. 제공자와 회원 번호 조합으로 시연 계정을 구분하며 실제 소셜 계정 연결은 아닙니다. 계정 변경·로그아웃 버튼으로 다른 회원의 장바구니와 예약이 분리되는지 확인할 수 있습니다.
- 한 번의 시연 결제에 공통 결제번호가 부여되고, 프로그램·날짜·회차별로 인원을 묶은 티켓이 각각 발급됩니다. 내 티켓에는 해당 계정의 모든 예약을 표시하며, 입장 상태 예시는 별도 체크박스로 확인합니다. 예시 티켓은 중복 검사에 포함되지 않습니다.
- 예약과 장바구니는 해당 브라우저에만 저장되며 다른 기기와 공유되지 않습니다. 기존 계정 정보가 없는 `ponylandReservations` 데이터는 변경하지 않고, 임의로 새 회원에게 귀속시키지도 않습니다.

## 검증 및 실제 서비스 연동 시 주의

```sh
node --test tests/*.test.cjs
```

시간 구간 중복, 계정 구분, 할인·금액, 회차별 티켓, 결제 재검증과 티켓 상태를 검사합니다. 장바구니 변경과 결제 직전에 최신 저장 데이터를 재검증하고, 지원되는 브라우저에서는 Web Locks로 같은 출처의 여러 탭에서의 저장 작업을 직렬화합니다. 결제 완료는 예약 전체 추가와 장바구니 비우기를 한 번에 저장한 뒤 표시합니다.

**실서비스의 보안·동시성 보장은 아직 없습니다.** 실제 연동 시 인증된 서버 회원 ID를 사용하고, 모든 기기의 기존 예약·진행 중 결제에 대한 시간 중복 검사를 서버 트랜잭션에서 실행해야 합니다. PG 승인 검증·중복 결제 방지·정원 관리도 서버에서 보장해야 합니다. 브라우저의 시연 회원 ID나 가격·예약 정보를 신뢰하면 안 됩니다.

## 수정 내용 배포하기

원본 HTML·CSS·JavaScript 또는 이미지를 수정한 뒤 아래 명령으로 공개용 파일을 갱신합니다.

```sh
node scripts/build-pages.mjs
```

갱신된 `docs/` 폴더를 함께 커밋하고 `master` 브랜치에 푸시하면 GitHub Pages가 자동으로 배포합니다. 웹사이트에는 지정된 페이지와 이미지 파일만 게시됩니다.
