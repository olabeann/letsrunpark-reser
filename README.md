# 렛츠런파크 통합 예약·결제 프로토타입

서울 렛츠런파크의 체험 예약과 고객사 운영 관리자를 검토하는 프론트엔드 프로토타입입니다. 현재 판매 화면은 **포니 타기·포니랑 놀기**이며, 계정·권한 관리는 운영 관리자 메뉴에 포함됩니다.

로그인·결제·환불·예약 저장은 화면 검토용 동작입니다. 실제 소셜 로그인, PG, 서버 DB와 권한 검증은 별도 연동해야 합니다. 예시 운영 데이터는 브라우저 저장소에 보관됩니다.

## 화면 구성

| 영역 | 메뉴·동선 | 파일 |
| --- | --- | --- |
| 이용자 예약 | 체험·날짜·회차·인원·할인 선택 → 장바구니 또는 바로 예약 → 결제 → 예약 완료 | `index.html`, `app.js` |
| 예약 조회 | 로그인 → 티켓 목록 → 상세·입장 상태 → 인원 선택 취소·환불 내역 | `reservations.html`, `ticket.html`, `app.js` |
| 운영 관리자 | 예약·티켓 / 프로그램·회차 / 운영일 관리 / 매출·정산 | `admin.html`, `admin.js` |
| 운영 관리자의 계정·권한 | 부서 계정 발급·수정·비밀번호 재발급·삭제 | `account-admin.html`, `account-admin.js` |
| 지역 안내 | 부산경남·제주 준비 중 안내 | `busan.html`, `jeju.html` |
| 오류 안내 | 결제 예외 / 시스템 오류 | `payment-failed.html`, `error.html` |

- 계정·권한 메뉴는 통합 관리자에게만 노출됩니다. 부서 공용 계정은 담당 부서 범위에서 운영합니다.
- 할인 관리는 프로그램·회차 메뉴 아래에서 접근합니다.
- 날짜·회차·인원·할인은 하나의 예약 화면 안에서 선택합니다.
- 부산경남·제주는 안내 화면이며 실제 지역별 예약은 확장 범위입니다.

## 핵심 운영 기준

- 카카오·네이버 로그인 회원만 예약합니다. 로그인 제공자가 다르면 별도 회원으로 식별합니다.
- 프로그램별 계정당 **이용일 하루 최대 구매 수량을 설정하며 기본값은 4매**, 과천시민 50% 할인은 같은 기준으로 **최대 2매**입니다.
- 장바구니에는 동일 이용일·지역·담당부서만 담습니다. 1명 카드별 반복 담기·삭제를 제공하며 담기·결제 진입으로 정원을 확보하지 않습니다.
- 다른 프로그램의 회차 시간이 기존 유효 예약 또는 장바구니와 겹치면 예약을 제한합니다. 같은 프로그램의 같은 회차는 여러 매 구매할 수 있습니다.
- 한 번의 결제에는 예약번호 하나를 발급하고, 프로그램·회차·인원은 하위 티켓으로 구분합니다.
- 선택 인원만 부분취소할 수 있으며 나머지 예약은 유지합니다. 취소 설정은 기본 10분 전이지만 실제 버튼은 입장 대기 상태도 요구하여 기본 20분 전부터 막힙니다. 이 안내·동작 차이는 요구사항 S-01에 기록했습니다.
- 과천시민 할인은 온라인 할인 결제 후 현장 증빙을 확인합니다. 구매 한도는 취소 완료 수량을 제외해 복원하며, 증빙 실패와 할인 집계·복원 설정 연결 차이는 요구사항의 확인 항목을 따릅니다.
- 현장 키오스크와 API로 연동하지 않으며 온라인 판매 수량을 별도로 관리합니다.
- 정산은 서비스 제공 완료일 기준입니다. 월별 정산 후 다음 달 8일 지급, PG 수수료 2% 및 취소 수수료 조정을 기준으로 합니다.
- 실서비스에서는 서버가 인증·권한·가격·할인·재고·구매 한도를 검증하고 PG 승인·환불 결과와 예약 데이터를 일관되게 처리해야 합니다.

## 실행과 검증

별도 빌드 없이 `index.html`을 열 수 있습니다. 같은 브라우저에서 화면 간 저장소를 일관되게 사용하려면 로컬 HTTP 서버로 확인합니다.

```sh
python -m http.server 4173
```

브라우저에서 `http://localhost:4173/` 또는 `http://localhost:4173/admin.html`을 엽니다.

```sh
node --test tests/*.test.cjs
```

테스트는 프로토타입 로직을 검증합니다. 실제 로그인·PG·서버 권한·동시 결제 통합 검수는 별도로 수행해야 합니다.

## 정책 보기

예약·운영 관리자·계정·권한 화면에서 `Alt + P`를 누릅니다. 정책 표시 영역을 선택하면 서비스 기준과 FE·BE 처리를 확인할 수 있습니다. `Esc`로 상세와 정책 보기를 닫습니다.

## 산출물 갱신

IA 내용을 변경할 때:

```sh
node outputs/build-ia.mjs
```

화면·스크립트·스타일·이미지를 변경할 때:

```sh
node scripts/build-pages.mjs
```

`docs/`는 원본의 공개 배포용 복사본이므로 중복 파일이라는 이유로 삭제하지 않습니다. 배포 스크립트는 허용 목록 밖 파일을 발견하면 중단합니다. 공개 파일을 제거할 때는 원본·허용 목록·해당 배포 복사본을 함께 정리해야 합니다.

생성된 `docs/`를 포함해 `master`에 커밋·푸시하면 GitHub Pages 배포에 반영됩니다. 요구사항·견적서·IA 등 내부 문서는 자동 공개하지 않습니다.

## 화면별 HTML 이동

`scripts/build-pages.mjs`는 `index.html`·`admin.html`의 공통 마크업으로 화면별 HTML 진입점을 생성합니다. 공통 UI 변경은 `index.html`에서 하고 생성된 화면 파일은 직접 수정하지 않습니다. 로그인·확인·할인 선택 등 대화상자는 해당 페이지 안에서 열립니다. 관리자 이전 해시 주소도 새 파일로 연결됩니다. 화면 이동은 실제 문서 이동이며 로그인은 sessionStorage, 예약·장바구니는 기존 localStorage로 유지합니다. 이전 `?product=`·`?view=` 링크도 새 파일로 연결됩니다.


화면별 HTML의 DOM 초기화·로그인·결제 후 저장·티켓 이동 검증은 `scripts/check-pages-dom.cjs`로 재현할 수 있습니다. 이 추가 검증은 `jsdom`이 필요하며 기본 `node --test`에는 외부 의존성이 없습니다. `jsdom`을 설치한 환경에서 `TZ=Asia/Seoul node scripts/check-pages-dom.cjs`를 실행합니다. 실제 브라우저의 렌더링 검증과는 별도입니다.

고객 예약 흐름: `booking.html` → `cart.html` → `checkout.html` → `complete.html` → `reservations.html` → `ticket.html`. 관리자 메뉴: `admin.html`, `admin-reservations.html`, `admin-operations.html`, `admin-settlement.html`, `admin-program-edit.html`, `admin-program-sessions.html`.

## 추석 연휴 한시 운영 예시

`holiday-demo.js`는 최초 방문 시 기존 브라우저 데이터를 유지하면서 ‘포니타기 추석 연휴’ 프로그램과 회차를 추가합니다. 운영 기간은 2026-09-24~26, 1인 5,000원, 4개 회차(각 정원 8명)이며 관리자에서 수정하거나 삭제한 예시는 다시 생성하지 않습니다. 관리자 예약 목록에는 10건·40매, 결제 200,000원 및 2매 환불 10,000원의 가상 데이터가 표시됩니다.

- 사용자 확인: `booking.html?product=ride-chuseok-2026`
- 정산 확인: `admin-settlement.html?example=chuseok` 또는 정산 화면의 ‘추석 연휴 정산 예시’ 링크

정산 예시는 2026-10-01 기준의 가상 서비스 완료를 가정합니다. 별도 상품 순매출은 190,000원, PG 수수료 2% 차감 후 지급예정액은 186,200원입니다. 일반 정산 조회에는 현재 시점 이후 서비스 완료 건을 포함하지 않습니다. 정산 화면과 엑셀 다운로드는 동일한 조회 기준을 사용합니다.
