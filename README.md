# 렛츠런파크 통합 예약·결제 프로토타입

서울 렛츠런파크의 체험 예약과 고객사 운영 관리자를 검토하는 프론트엔드 프로토타입입니다. 현재 판매 화면은 **포니 타기·포니랑 놀기**이며, 계정·권한 관리는 운영 관리자 메뉴에 포함됩니다.

로그인·결제·환불·예약 저장은 화면 검토용 동작입니다. 실제 소셜 로그인, PG, 서버 DB와 권한 검증은 별도 연동해야 합니다. 예시 운영 데이터는 브라우저 저장소에 보관됩니다.

## 화면 구성

| 영역 | 메뉴·동선 | 파일 |
| --- | --- | --- |
| 이용자 예약 | 체험·날짜·회차·인원·할인 선택 → 장바구니 또는 바로 예약 → 결제 → 예약 완료 | `index.html`, `app.js` |
| 예약 조회 | 로그인 → 티켓 목록 → 상세·입장 상태 → 인원 선택 취소·환불 내역 | `index.html`, `app.js` |
| 운영 관리자 | 예약·티켓 / 프로그램·회차 / 운영일 관리 / 매출·정산 | `admin.html`, `admin.js` |
| 운영 관리자의 계정·권한 | 부서 계정 발급·수정·비밀번호 재발급·삭제 | `account-admin.html`, `account-admin.js` |
| 지역 안내 | 부산경남·제주 준비 중 안내 | `busan.html`, `jeju.html` |
| 오류 안내 | 결제 예외 / 시스템 오류 | `payment-failed.html`, `error.html` |

- 계정·권한 메뉴는 통합 관리자에게만 노출됩니다. 부서 공용 계정은 담당 부서 범위에서 운영합니다.
- 할인 관리는 프로그램·회차 메뉴 아래에서 접근합니다.
- 날짜·회차·인원·할인은 하나의 예약 화면 안에서 선택합니다.
- 부산경남·제주는 안내 화면이며 실제 지역별 예약은 확장 범위입니다.

## 핵심 운영 기준

- 카카오·네이버 로그인 회원만 예약합니다. 로그인 제공자가 다르면 별도 회원으로 식별합니다.
- 포니 프로그램은 계정별 **이용일 하루 합산 최대 4매**, 과천시민 50% 할인은 같은 기준으로 **최대 2매**입니다.
- 장바구니에는 하나의 이용일만 담습니다. 담기만으로 정원을 확보하지 않습니다.
- **시간이 겹쳐도** 온라인 잔여 수량과 이용일 구매 한도 안에서 여러 이용자의 티켓을 함께 예약할 수 있습니다.
- 한 번의 결제에는 예약번호 하나를 발급하고, 프로그램·회차·인원은 하위 티켓으로 구분합니다.
- 선택 인원만 부분취소할 수 있으며 나머지 예약은 유지합니다. 기본 사용자 취소 마감은 이용 시작 10분 전이며 프로그램별 설정을 적용합니다.
- 과천시민 할인은 온라인 할인 결제 후 현장 증빙을 확인합니다. 증빙 실패·한도 복원 등 세부 처리는 확정 요구사항의 확인 항목을 따릅니다.
- 현장 키오스크와 API로 연동하지 않으며 온라인 판매 수량을 별도로 관리합니다.
- 정산은 서비스 제공 완료일 기준입니다. 월별 정산 후 다음 달 8일 지급, PG 수수료 2% 및 취소 수수료 조정을 기준으로 합니다.
- 실서비스에서는 서버가 인증·권한·가격·할인·재고·구매 한도를 검증하고 PG 승인·환불 결과와 예약 데이터를 일관되게 처리해야 합니다.

## 실행과 검증

별도 빌드 없이 `index.html`을 열 수 있습니다. 같은 브라우저에서 화면 간 저장소를 일관되게 사용하려면 로컬 HTTP 서버로 확인합니다.

```sh
python -m http.server 4173
```

브라우저에서 `http://localhost:4173/` 또는 `http://localhost:4173/admin.html`을 엽니다.

```sh
node --test tests/*.test.cjs
```

테스트는 프로토타입 로직을 검증합니다. 실제 로그인·PG·서버 권한·동시 결제 통합 검수는 별도로 수행해야 합니다.

## 정책 보기

예약·운영 관리자·계정·권한 화면에서 `Alt + P`를 누릅니다. 정책 표시 영역을 선택하면 서비스 기준과 FE·BE 처리를 확인할 수 있습니다. `Esc`로 상세와 정책 보기를 닫습니다.

## 산출물 갱신

IA 내용을 변경할 때:

```sh
node outputs/build-ia.mjs
```

화면·스크립트·스타일·이미지를 변경할 때:

```sh
node scripts/build-pages.mjs
```

`docs/`는 원본의 공개 배포용 복사본이므로 중복 파일이라는 이유로 삭제하지 않습니다. 배포 스크립트는 허용 목록 밖 파일을 발견하면 중단합니다. 공개 파일을 제거할 때는 원본·허용 목록·해당 배포 복사본을 함께 정리해야 합니다.

생성된 `docs/`를 포함해 `master`에 커밋·푸시하면 GitHub Pages 배포에 반영됩니다. 요구사항·견적서·IA 등 내부 문서는 자동 공개하지 않습니다.
