INTERNAL DEVELOPMENT POLICY

렛츠런플레이 예약 시스템
개발 정책서

고객사 메일과 미팅에서 확인된 MVP 구현 기준입니다.

링크 비공개최종 정리 2026. 09. 03.
공유 주의이 페이지는 관리자 화면이나 사용자 화면에서 연결되지 않으며 검색엔진 수집을 차단합니다. 다만 로그인으로 보호된 문서가 아니므로 URL을 외부에 공유하지 마세요.

01회원 확정

  • 네이버·카카오 간편로그인만 제공하며 비회원 예약은 허용하지 않습니다.
  • 로그인 제공자가 다르면 별도 계정으로 식별하며 계정 통합은 제공하지 않습니다.
  • 한 계정으로 보호자가 여러 어린이의 티켓을 예약할 수 있습니다.

02프로그램·회차 확정

  • 프로그램을 먼저 등록하고 그 하위에 반복 회차를 등록합니다.
  • 프로그램에는 지역·부서·유형·명칭·가격·운영 일정·취소 마감·할인을 저장합니다.
  • 회차에는 시작·종료 시간, 온라인 판매 수량, 판매 상태만 저장합니다.
  • 회차명은 시간순으로 자동 생성합니다.
  • 사용자 안내문과 현장 판매 수량은 예약 관리자 입력 항목에서 제외합니다.

03예약·할인·취소 확정

  • 기본 예약 범위는 이용일 기준 향후 14일이며 운영 기간·요일과 회차 템플릿으로 실제 회차를 생성합니다.
  • 포니 타기와 포니랑 놀기를 합쳐 장바구니 최대 4매이며 두 프로그램의 겹치는 시간 예약을 차단합니다.
  • 과천시민 할인은 50%, 계정당 평생 최대 2매이며 두 포니 프로그램을 합산합니다.
  • 할인 금액으로 온라인 결제하고 증빙은 현장에서 확인합니다.
  • 사용자 취소 마감은 기본 10분 전이며 프로그램별로 분·시간·일 단위 설정이 가능합니다.
  • 결제 직전 서버에서 온라인 재고·구매 한도·시간 충돌·할인 사용량을 재검증합니다.

04티켓·권한·정산 확정

  • 같은 프로그램·같은 시간대의 복수 인원은 한 티켓에 인원수로 표시합니다.
  • 다른 프로그램 또는 다른 시간대는 별도 티켓으로 표시합니다.
  • 모든 부서는 전체 프로그램을 조회할 수 있고 수정·삭제는 담당 부서만 가능합니다.
  • 정산은 서비스 제공 완료일 기준이며 지역·부서·프로그램별로 구분합니다.

05고객사 확인 필요 미확정

  1. 4매 구매 제한의 분할 주문 집계 기간
  2. 구매·할인 사용량의 취소 및 환불 시 복원 여부
  3. 과천시민 증빙 미제출 시 차액 결제 또는 이용 제한 기준
  4. 월 정산 지급일과 투어 예외 환불의 차월 차감 기준
  5. 고객 연락처를 받지 않는 상태에서 운영 취소 사실을 전달할 방식

06운영 버전 필수 구현

  • DB는 프로그램 → 회차 템플릿 → 날짜별 실제 회차 구조로 분리하고 외래키로 연결합니다.
  • 현장 키오스크는 API 미연동이므로 온라인 예약 DB에서 현장 재고를 계산하거나 차감하지 않습니다.
  • 프로토타입의 브라우저 저장소를 서버 DB로 교체하고 네이버·카카오 SSO 및 PG를 연동합니다.
  • 재고 차감과 주문 생성은 하나의 트랜잭션으로 처리하고 중복 결제·초과 예약을 방지합니다.
  • 주문에는 결제 시점의 프로그램명·가격·할인·회차 정보를 스냅샷으로 보관해 이후 프로그램 수정이 과거 예약을 바꾸지 않게 합니다.
  • 지역·부서·프로그램 기준 권한 검증과 관리자 변경 이력을 서버에서 기록합니다.
  • 정책 값은 프로그램 코드에 직접 넣지 않고 정책·할인·프로그램 관계 데이터로 관리합니다.
문서 기준: 한국마사회 고객사 메일 및 미팅 논의사항 · 화면은 정책 검토용 프로토타입입니다.
