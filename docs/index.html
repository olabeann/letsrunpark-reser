FE · BE 동작 정책

현재 화면에 필요한 동작과 서버 검증 규칙만 표시합니다.

회원

  • 네이버·카카오 로그인만 제공하며 비회원 예약은 허용하지 않습니다.
  • 로그인 제공자가 다르면 별도 계정으로 식별하고 계정 통합은 제공하지 않습니다.
  • 한 계정으로 여러 어린이의 티켓을 예약할 수 있습니다.

프로그램·회차 구조

  • 프로그램을 먼저 등록하고 그 하위에 반복 회차를 등록합니다.
  • 프로그램에는 지역·부서·유형·명칭·기본 가격·운영 일정·노출 기간·판매 기간·취소 가능 시간·할인을 저장합니다.
  • 회차에는 시작·종료 시간, 온라인 판매 수량, 판매 상태만 저장합니다.
  • 회차명은 시간순으로 자동 생성하며 사용자 안내문과 현장 판매 수량은 입력받지 않습니다.
  • 현장 키오스크는 API 미연동이므로 온라인 관리자에서 현장 재고를 관리하지 않습니다.

예약·재고

  • 예약 판매 시작일과 종료일은 날짜 단위로 동일하게 설정합니다.
  • 판매 기간 안에서도 사용자가 선택할 수 있는 이용일은 오늘 기준 향후 14일까지입니다.
  • 노출 기간에는 프로그램을 표시하고, 판매 가능 기간에만 예약 버튼을 활성화합니다.
  • 운영 기간·요일과 회차 템플릿으로 실제 이용일 회차를 생성합니다.
  • 포니 타기와 포니랑 놀기를 합쳐 이용일 하루 기준 계정당 최대 4매이며, 이미 확정된 예약과 새 주문을 합산합니다.
  • 장바구니에는 하나의 이용일만 담을 수 있습니다.
  • 두 프로그램은 시간이 겹치면 같은 계정에서 동시에 예약할 수 없습니다.
  • 결제 직전에 계정·온라인 재고·시간 충돌·할인 사용량을 서버에서 다시 검증합니다.

할인·취소

  • 과천시민 할인은 50%이며 이용일 하루 기준 계정당 최대 2매이고 두 포니 프로그램을 합산합니다.
  • 할인은 정률·정액, 1매당 최대 할인 금액, 적용 수량·집계 기준, 적용 기간·프로그램·증빙 방식으로 관리합니다.
  • 할인을 비활성화하거나 설정을 변경해도 기존 예약의 결제 당시 할인 내역은 변경하지 않습니다.
  • 할인 금액으로 온라인 결제하고 증빙은 현장에서 확인합니다.
  • 사용자 취소 마감은 기본 10분 전이며 프로그램별로 분·시간·일 단위 설정이 가능합니다.
  • 부분취소는 선택한 인원의 금액만 환불하며 나머지 인원의 예약은 유지합니다. 예: 4매 결제 후 1매 취소 시 나머지 3매는 예약이 유지됩니다.
  • 관리자는 기상·시설·안전 사유로 회차 전체를 취소하고 환불할 수 있습니다.

계정·권한

  • 담당 부서별 공용 관리자 계정 1개와 별도의 통합 관리자 계정을 발급합니다.
  • 위이가 로그인 ID와 임시 비밀번호를 발급해 담당 부서에 전달합니다.
  • 전체 프로그램은 조회할 수 있고, 관리 작업은 권한이 있는 자기 부서 데이터에만 허용합니다.
  • 프로그램·회차, 예약 조회, 취소·환불, 매출·정산 권한을 계정별로 설정합니다.
  • 비밀번호는 저장 후 다시 노출하지 않으며 분실 시 임시 비밀번호를 재발급합니다.
  • 화면뿐 아니라 모든 서버 API에서 부서와 권한을 검증합니다.

티켓·정산

  • 같은 프로그램·같은 시간대의 복수 인원은 한 티켓에 인원수로 표시합니다.
  • 다른 프로그램 또는 다른 시간대는 별도 티켓으로 표시합니다.
  • 주문에는 결제 시점의 프로그램명·가격·할인 정보를 스냅샷으로 보관합니다.
  • 정산은 서비스 제공 완료일 기준이며 지역·부서·프로그램별로 구분합니다.

고객사 확인 필요

  1. 구매·할인 사용량의 취소 및 환불 시 복원 여부
  2. 과천시민 증빙 미제출 시 차액 결제 또는 이용 제한 기준
  3. 월 정산 지급일과 투어 예외 환불의 차월 차감 기준
